# Customer-connected ChatGPT investigator and evidence analysis sandbox

**Design for review · 26 November 2026 · baseline `c862712`.** An incident may outlast a model attempt, its credentials and its transcript. Give the operator one account connection, keep the next investigative question in the controller, and let either engine compute over evidence that the run has already obtained. This proposal covers incident work. The existing discovery and scheduled host-review paths retain their own purposes and grants. [Development charter](DSAMH_Adaptive_Autonomous_Investigator_Development_Direction.md) · [Adaptive investigator](adaptive-investigator.md)

## 1. Connect your ChatGPT account and choose an engine

1. **Connect locally.** On the customer-operated controller, a dedicated reasoner service identity owns the private OAuth registry. Run the existing `defsec-reasoner chatgpt login --profile NAME` flow as that identity. The operator authorizes in a browser through the local loopback callback. For a headless controller, qualify the documented self-hosted VM callback flow before offering it. Keep PKCE, state, nonce, issuer/audience/subject verification and the separate plan-sharing scope check. Only the connection owner reads the refresh token. Neither model receives credentials in context. [OAuth implementation](../../reasoner/defsec_reasoner/chatgpt_auth.py) · [Self-hosted VMs](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)
2. **Choose model, effort and engine.** List models with `chatgpt models --profile NAME`. Record the selection per worker deployment. A successful synthetic inference turn confirms access for that request. Customer-hosted, locally running open-source tools are within the documented plan-sharing use case. OpenAI directs paid or remotely hosted apps to request access before offering the integration. A customer subscription alone does not establish eligibility for a hosted service. [OpenAI integration scope](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt)
3. **Define scope.** Select host IDs, allowed collectors, field projection, redactions, destination, retention and budgets. Evaluate read and external export grants independently on every turn, including findings, derived output and resumed history. Start with synthetic inputs only.
4. **Qualify and enable.** Replay an isolated synthetic incident through the selected engine. Require a scoped fetch, cited finding, denied export of a marked field, and dry-run response with the expected verification status. Show the operator exactly what the provider received. Enable live ingestion/export for the selected hosts only after explicit activation.

The helper receives the access token alone. Its OS identity cannot read the OAuth registry, parent run credential, signing material or controller sockets. Give it only its private home, trusted runtime, stdio broker and approved inference egress. A dedicated supervisor can pass the child environment at launch without using global environment, argv, config files or logs. Direct and helper modes use the same customer authorization without a CLI login. The current `investigator` / `codex-worker` uses `codex exec` and its own CLI session (ephemeral by default, with opt-in session persistence). Bare `worker` runs the custom adapter loop, and `worker --backend codex` is rejected in favor of explicit `codex-worker` / `investigator`. Preserve existing invocations and adapter selectors, and dispatch the new helper only on explicit selection. **Cache accounting.** OpenAI introduced the Responses API 12-hour option on 20 October 2026. On supported newer models the default minimum is 30 minutes. Longer-lived eligible prefixes incur more expensive writes. A minimum pricing lifetime promises neither permanent residency nor faster execution. Cross-route reuse and support for a requested TTL through plan OAuth or app-server require measurement. Keep stable tool definitions first where supported. Record requested/effective settings and reported reads/writes, with unavailable metrics marked unknown. Local thread resume and prompt caching have independent lifetimes. [API changelog](https://developers.openai.com/api/docs/changelog) · [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)

**Independent controls.** Pause stops new leases, fences ongoing turns and checkpoints unfinished work. Revocation blocks new provider sends, stops helpers, invalidates session bindings and invokes profile logout. Report local disconnection and remote revocation confirmation separately. Transcript purge fences the helper, invalidates its pointer, deletes the entire scoped private home and verifies deletion before allowing a fresh start. Retry incomplete deletion after restart. Apply the same process at configured expiry. Record who requested each operation and its outcome. Case revisions, evidence retention and the controller audit chain have separate lifecycles.

## 2. A durable incident case in control-d

Use one case per incident in the first migration. The incident supplies host and open/closed status. An engine attempt remains an existing `agent_runs` row. The proposed SQLite records below use existing text IDs, integer observation/finding IDs and UTC timestamps. Existing incidents become eligible on first authorized case access. Seed from attributable existing rows and mark missing questions or evidence unknown. [Base schema](../../crates/control-d/src/schema.sql) · [Follow-up state](../../crates/control-d/src/schema_v8.sql) · [Effect checks](../../crates/control-d/src/schema_v11.sql)

| Proposed record and key | Fields and integrity rules |
|---|---|
| `case_heads(incident_id PK/FK incidents)` | `current_rev INTEGER`, monotonically increasing, references the same incident's revision. |
| `case_revisions(incident_id, rev)` composite PK | Immutable checkpoint with `run_id` (nullable for controller events), `writer`, `committed_at`, `request_key`, request digest, `open_question`, `state` (active, waiting, paused, closed), `reason`, nullable `last_verified_receipt_id` FK to effect checks. Unique (incident_id, request_key). Only control can set the verified pointer from a verified check for this incident. Preserve the last verified result when a later check is pending or contradicted and display both. |
| `case_claims(incident_id, rev, claim_id)` composite PK | Stable claim ID across revisions, bounded statement, hypothesis/finding kind, tentative/supported/contradicted/withdrawn status, optional FK to this incident's finding. `case_citations(incident_id,rev,claim_id,observation_id)` binds each claim to raw observation IDs, stored state hash and supporting/conflicting role. Require citations for supported claims. |
| `case_tasks(incident_id,rev,task_id)` composite PK | Question, due time, observation cursor, pending/completed/expired/cancelled state, optional FK to `watch_followups.proposal_id` or `action_effect_checks.receipt_id`. Use the linked job's live status on read. Reuse the job across attempts. |
| `case_sessions(incident_id,engine)` composite PK | Optional opaque local thread ID, pinned helper version, model, transcript expiry, connection generation, controller-keyed HMAC of verified issuer/client/subject, and digest of effective investigator grants, export policy, destination and principal. Only the supervisor can update this row under a valid lease. No bearer or refresh token. |

All revision children reference their parent. Validate size/count limits, incident/host ownership, readability and hashes of every referenced observation. Treat free text and computed summaries as derived from the entire contributing input set. Store dependency IDs and export classification for each context field, including questions and tasks. Omit derived text if any dependency fails current authorization. Scope legacy text with unknown provenance to operator review.

On wake, lease a trigger, mint a fresh scoped child, read the head and recheck visibility. Commit a complete bounded revision, citations, tasks, head swap and audit outbox entry atomically under expected revision and valid run/lease. Replaying an identical request key returns the committed revision. A changed payload conflicts. A stale writer must reload and reconcile. Checkpoint before waiting on telemetry or a provider. Persist proposal keys and job IDs before dispatch, and reconcile uncertain effects before retry, including finding submissions whose current RPC lacks idempotency. On close or cancellation fence outstanding work. A later authorized attempt can read the last committed question even if the original process never returned.

Resume a local thread only after validating the current grant/account binding, expiry, model/version, case revision and authorized history manifest. A scope reduction, changed subject, account reconnection, changed case revision since the transcript checkpoint, unconfirmed history, or missing home forces a fresh thread from the filtered case. Store the checkpoint revision and manifest digest alongside the pointer. During quota exhaustion or provider outage the controller retains the question, citations and due jobs. Provider changes and transcript deletion require only rehydrating that authorized record. ## 3. Read-only Python analysis of fetched evidence

Offer both engines one typed operation, `analyze_evidence(observation_ids, script)`, bound by the broker to the active run. For example, an investigator can count distinct service transitions in a journal slice and compare them with a baseline diff. A partial journal produces a count for the supplied interval plus a coverage gap. A new host sample requires a separate typed collector request.

1. **Freeze inputs.** Check the lease, analysis grant and run's audited fetch ledger. Accept only named IDs previously fetched by this run and still readable. A trusted materializer writes newly serialized regular JSON files under generated names in an immutable snapshot. Include authorized baseline diffs and journal slices with their source IDs, digest, time range, status and truncation. Reject oversized selections. Never resolve a telemetry string or model argument as a filesystem path.
2. **Launch a separate local runner.** Give a dedicated unprivileged UID an empty mount root, immutable minimal Python runtime and standard library, a read-only snapshot, and a private writable tmpfs scratch directory. Use bubblewrap namespaces including private PID, IPC, mount and network (`--unshare-net`), drop all capabilities, set no-new-privileges and enforce a tested syscall allowlist. Deny socket creation, namespace changes, mount, tracing and additional processes. Close inherited descriptors except controlled input/output pipes, clear environment, and expose no host mounts, procfs, devices, controller UDS, keys, OAuth state or helper home. Deliver source as data to the fixed interpreter. Fetches, dependency installation and native shell tools are outside this interface.
3. **Enforce limits externally.** Proposed pilot ceilings per invocation are 16 KiB source, 64 snapshot files/4 MiB total, 2 CPU seconds, 5 wall seconds, 128 MiB memory, 16 open descriptors, 4 MiB scratch and 64 scratch inodes, 8 KiB stdout and 2 KiB stderr. Use cgroup memory/process limits, CPU rlimit, supervisor deadline, size/inode-limited tmpfs and separate capped pipe readers. Open-file limits alone do not bound created files. Kill the whole job on limit, cancellation or grant loss, remove mounts and scratch, and mark partial output unusable. Limit to three calls per attempt initially.
4. **Prove isolation at startup.** Run the production profile against harmless synthetic files and sentinel socket endpoints. Verify permitted reads and scratch writes, denied host access and network, immutable snapshot and each resource ceiling. Bind results to kernel/runtime/profile digest and recheck at runner start. Missing namespaces, quotas, seccomp or failed probes disable the tool with a reason. Typed reads remain available.
5. **Record and return.** Before launch persist an analysis ID, script SHA-256, snapshot manifest digest and input IDs. The broker records completion in `run_events` with runtime/profile digest, elapsed time, byte counts, truncation, exit status/signal and bounded redacted summary, including denial, timeout or interruption. Pair start/finish by analysis ID and reconcile missing finishes on restart. Wrap permitted output as untrusted computed analysis tagged with analysis and source IDs. Escape delimiters and recheck the full input set against current export policy before returning output to either model. A model-generated statistic can support a finding citing original observations. It cannot create an observation, satisfy an action evidence minimum or verify an effect. [Run events](../../crates/control-d/src/schema_v4.sql) · [Evidence boundary](../security-model.md)

## 4. Signed mitigation and independent verification

The investigator can submit a typed action proposal with scoped evidence IDs, rationale, target, expected effect, precondition and rollback. Control evaluates policy, persists the intent and obtains the required approval. Phase 8 delivers the expiring signed intent to the separate executor, which verifies signatures, local allowlists and protected resources, expiry and persistent nonce/replay state before execution. A model, Python process or helper holds no signing authority. Today delegated actions require the independent operator signature. Preserve that default. [Action admission](../../crates/control-d/src/actions.rs) · [Security model](../security-model.md)

Any later preauthorization requires an explicit change to delegated policy and opt-in at both control and executor. Permit only a named reversible verb/target on an enrolled host under a time-limited operator grant with a use cap, tested rollback, fresh precondition and supported independent verifier. Protected units and CIDRs always take precedence. Recheck grant, expiry, stop switch and local floors at admission and before dispatch/execution. Stop blocks queued work, records in-flight work for reconciliation and never promises to undo an executed change. Keep unsupported verbs on the approval path and report missing verification coverage.

Phase 18 binds the service-state precondition to the host, unit, watch revision and session. An eligible receipt starts a bounded independent observation window. Only a qualifying fresh post-action observation can establish the expected service state. Show receipt, expected state, observed state, observation ID, deadline and any observed collateral change together. Use the existing awaiting_evidence, verified, contradicted and indeterminate results. Missing telemetry leaves the effect indeterminate at expiry. Record later recovery separately. A transport cut or uncertain execution requires reconciliation before another action on the target. Recovery goes through the signed path and requires its own observation. ## 5. Milestones, comparison and decisions

| Milestone after approval | Exit evidence |
|---|---|
| 1. Case persistence and explicit routing | Migrate a preexisting incident. Restart after a fetch, fence a stale writer and resume with a different adapter. Demonstrate one follow-up job, valid citations and independently enforced export scope. Exercise legacy CLI invocations. |
| 2. Account connection and helper qualification | One local login completes a synthetic incident through both explicit engines. Force refresh, account swap, narrower scope, pause, failed revocation and transcript purge. Check for stale output, wrong-subject resume and credential leakage. Record qualifying binary digest and protocol version. |
| 3. Analysis broker | Both engines solve the same counting task with the same snapshot. Deterministically exercise every denied resource and limit, unavailable isolation, cancellation and runner crash. Verify complete audit accounting and export refusal for derived restricted data. |
| 4. Response boundary | Use disposable fixtures to check signed dry-run, operator approval, stale data, ineffective action, independent verification and recovery. Keep optional delegated preauthorization a separate decision and test its expiry, denylist and stop behavior before enablement. |
| 5. Paired engine trial | Publish case-level results and uncertainty. Select a default only after reviewing the matched evidence. |

Freeze incident fixtures, hidden answers and scoring before any model sees them. Include known drift, genuine change, partial evidence, an unresolved case and a response requiring fresh verification. Replay identical observations and timestamps to independent case databases, with the same permitted tools, model snapshot where available, effort, redactions and budgets. Randomize engine order across repeated pairs. Use actual elapsed gaps of 5 minutes and 10 hours, plus a cold resume beyond 12 hours. Test helper thread resume and a forced transcript purge. Record intervening refreshes, policy changes, provider limits and any settings the routes cannot match. Report unmatched configurations separately.

Score blinded, citation-correct conclusions, appropriate uncertainty, verified effects, operator interventions and unauthorized reads/exports/actions. Measure per-pair time to first useful result and verified conclusion, input/output/reasoning tokens, cache reads/writes, tool calls, retries and quota failures. Count all attempts in resource totals per verified conclusion. Report subscription usage as reported, API-equivalent estimates separately, and unavailable counters as unknown. Predeclare safety gates of zero unauthorized operations and zero false verified effects. Agree on an accuracy margin and efficiency metric before unblinding. If uncertainty spans the decision threshold, retain explicit selection and collect more pairs.

**Decisions requested before coding**

- Approve the locally operated deployment scope, explicit helper command and pilot model/account. Choose who may activate live export and the initial host/field policy.
- Approve one case per incident and the proposed revision model. Set case retention, transcript TTL and purge scope for the customer deployment.
- Approve the Linux-only analysis pilot, standard library and resource ceilings, or specify tighter budgets for the target controller.
- Approve operator-only response for the pilot. Identify any reversible target class to qualify later and who can issue or revoke its preauthorization.
- Choose paired trial size, allowable accuracy difference and primary efficiency metric within the available plan quota. Defer the default-engine decision until those results are available.
