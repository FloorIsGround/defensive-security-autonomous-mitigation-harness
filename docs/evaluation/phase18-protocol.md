# Phase 18 synthetic episode protocol v1

Run the cases below in order once per lane using a fresh local ledger and synthetic
agent per attempt. Share the observation stream, investigator collector scope,
baseline setup and maintenance permission across lanes. The adaptive lane may
use its product discovery and durable follow-up entry points. The P12 reactive
proxy runs the current trigger worker with only trigger handling. It models the
P12 execution boundary using a common adapter and does not benchmark Codex CLI.
Static uses the same control rules and leaves investigation triggers untouched.

| Case | Input | Episode passes when |
| --- | --- | --- |
| Quiet onboarding | PostgreSQL 16 package and TCP 5432 in one-shot discovery on a quiet host | No trigger and a persisted likely PostgreSQL purpose cites exactly the two samples |
| Permitted maintenance | Existing rule permits sshd on port 22, initially absent then present | No trigger and the rule registers a hit |
| New service | TCP 4444 appears for ghost.service, fresh unit sample active/running if watched | Trigger and durable supports assessment with exactly the fresh unit observation ID, explicitly describing active/running |
| Missing evidence | Same new listener, no unit sample delivered | Trigger, durable question still awaiting evidence and no verified finding claiming the unit state |

Discovery and active unit assessment are separately counted verified claims.
No idle or maintenance claim earns a claim count. Neither a mere trigger nor
the listener itself verifies unit state. Audit must validate for every pass.
Record a manual follow-up intervention as required when a triggered case ends
without a durable evidence question. Count one actual setup intervention for
the maintenance rule, and record any discretionary intervention separately
(none planned). Automated fixture delivery is not an intervention.

Run static, reactive scripted and adaptive scripted, followed by matched
reactive and adaptive OpenRouter GLM Flash if an existing key is available.
Use only the fixture telemetry on the live route. Grant discovery export only
for the synthetic host and discovery collectors. Give the trigger model a
shared operator objective to request a fresh unit-state watch and finish so
the sample can arrive asynchronously. Use three initial model turns at most,
one assessment turn, 25 seconds per request, 60 seconds per investigation,
one proposal and zero episode retries. Treat quiet discovery as one model
request. Keep each planned attempt in the denominator, including unavailable
routes, harness errors and unsupported baseline outcomes. Report device
delivery gaps separately from feature coverage and provider or export
availability. Use server-reported usage and cost per request when returned
and mark absent fields unknown. No fleet or remediation qualification.
